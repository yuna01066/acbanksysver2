## 구현

- 발행 견적 상세 편집에 재질·컬러 변경과 등록 기준/표시명 분리.
- 기존 재질/컬러 선택기와 `usePriceCalculation` 재사용. 공식과 단가표 신설 없음.
- 변경 품목만 재계산. 원판 장수/가공 수량/제품 수량/견적 품목 수량을 분리해서 복원.
- 다른 컬러의 조색비는 유지하지 않음. 현행 계산기 기본 40,000원을 공유하고 사용자가 원판별로 수정 가능. 0원도 유효.
- 기존 근거가 부족하면 자동 복원하지 않고 계산기에서 조건 재확인. 표시 사양 불일치, 누락 접착 조건은 확인 필요.
- 이전/이후 단가·사양 및 총액 차이 표시. 사양 변경 시 수동 총액 조정 해제, 취소·원래 사양 선택 시 복구. 제목만 수정 시 기존 금액 유지.
- 최신 입력으로 동기 계산하며 단가 로딩/실패/불가 상태와 검수 경고를 저장까지 연결.
- 상세와 계산기의 판재 수정 저장을 `save_issued_quote_revision` RPC로 통합. 예상 수정 시각 비교, 행 잠금, 이전 전체 스냅샷·수정 견적·처리자 이력의 트랜잭션 저장.
- RPC는 SECURITY INVOKER. 기존 테이블과 RLS 유지. 등록 컬러·단가표, 입력 유형, 수량, 계산 내역·총액, 수정 필드 제한 검증.
- 응답 불명확 시 읽기 재조회만 수행하고 자동 재전송하지 않음. 저장 실패 시 편집 내용 유지.
- 내부/고객 공통 출력 카드에서 표시명 사용. 내부에는 연결 기준도 표시. 기존 복제/재발행은 JSON 전체를 복사하므로 추가 정보 유지.
- 정적 첨부 PDF·발주·세금계산서는 그대로이며 저장 완료 시 재출력·확인 안내.

## 적용 순서

1. 작업 diff 검토 후 이 브랜치만 커밋·푸시.
2. 대상 프로젝트 `zwloyqcwyfkimwkohpnd`와 연결 브랜치/커밋 재확인.
3. 추가 마이그레이션 `20260923090000_issued_quote_revision.sql` 적용. 기존 마이그레이션 수정/재실행 및 과거 데이터 일괄 변경 없음.
4. RPC 존재/권한 확인 후 프론트엔드 반영. Edge Function 변경/배포 불필요.
5. 배포 자산, 격리 견적 저장·재조회·이력·PDF 검증. 기존 브라우저는 새로고침하여 이전 직접 저장 경로를 사용하지 않도록 안내.

PGlite는 프로젝트 의존성에 추가하지 않고 임시 테스트 폴더에만 설치했다. 테스트 스크립트는 DB URL/운영 자격증명을 받지 않는다. 프리뷰는 테스트용이며 production 라우트에 등록되지 않는다.
